# Grilling (Design Interview)

## When to Use
- Requirements are ambiguous or underspecified
- Multiple valid approaches exist and user preference matters
- Before starting a large implementation
- When scope needs narrowing

## Process
1. Read available context (repo structure, existing code, docs)
2. Identify open questions and decision points
3. Ask structured questions (batch 3-5 at a time)
4. Summarize decisions after each round
5. Produce a final design brief when alignment is reached

## Question Categories
- **Scope:** what's in, what's out?
- **Priority:** what matters most?
- **Constraints:** budget, timeline, compatibility requirements?
- **Preferences:** style, approach, technology choices?
- **Edge cases:** what happens when X fails?

## Rules
- Keep questions concrete, not abstract
- Offer options with tradeoffs, not open-ended questions
- Summarize decisions incrementally
- Stop grilling when enough clarity exists to proceed
