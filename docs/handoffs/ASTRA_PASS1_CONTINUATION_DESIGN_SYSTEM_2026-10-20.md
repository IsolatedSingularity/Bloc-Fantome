## One visual system throughout the application

- **Typography:** use the Windows-installed **Segoe UI** regular/semibold as the uniform application UI font, including splash/title overlay, editor, hotbar numbers/labels, settings, help, shortcuts, modal actions, Library and side previews, World Map *controls*, tutorial controls, Redstone Lab *controls*, loading, progress/errors, audio settings, notifications and new opening controls. A splash's title may use a restrained larger native-size Segoe treatment without restyling the owner's original painting. Prefer real family weights over fake bold and define a small consistent type scale (body, label, caption, heading, title), line-height/contrast, wrap/truncation and stable measurements. The current `Code/splash.py` explicitly matches `segoeui`; `Code/ui/fonts.py` defaults to Zekton and other UI paths bypass it. Consolidate both styles through a **small shared typography owner** without rewriting whole modules. Preserve Unicode/fallback behavior. Do **not bundle, copy or commit Microsoft Segoe font binaries**; resolve it via the OS, then choose a **properly licensed bundled fall-back** only if required for non-Windows builds, with attribution/notice and measured text reflow. Microsoft's Segoe UI Variable is not generally licensable for non-Windows distribution. Test system font availability before relying on a particular variable-font face, and record the actual family used.
- **Surface design:** one small shared token set for colors, spacing, corner radii, elevations/opacity, outlines, focus indicators, disabled/selected/active states, typography and motion. Quiet matte charcoal and faint cool glass/stone-tinted accent fit the artwork without a fake sci-fi HUD or fake chunky stone beveled panels. Remove doubled borders, noisy nine-slice framing and multiple incompatible button styles. Use generous breathing space, legible grouping and positive/negative space. Make the UI harmonious against bright grass, darkness, fog, storm, Nether, End and complex occupied builds; avoid generic dashboard cards and decorative gradients.
- **Block-texture leaking:** `Code/ui/chrome.py::panel` presently **tiles `assets.backgroundTile` into UI surfaces** and draws nested beveled strokes. Audit every caller, `drawButton`, UI atlas/background generation, alpha composition, fullscreen/windowed resize, camera/viewport clipping and paint/clear order. Eliminate undesired world/block texture bleed rather than covering defects with opacity. Source block-art thumbnails and Minecraft-like hotbar *items* can stay intentional; menu backgrounds must not accidentally inherit the same asset. Correct stale surfaces/cached sizes after resize or DPI change, drawing alpha/clipping, hit regions and layering, especially mixed OpenGL/SDL surfaces. If an approved Minecraft-themed texture remains in a deliberate scene-specific element, isolate it from the new shared chrome.
- **"Vector-quality" requirement:** Pygame fonts and image Surfaces are raster at the end. Implement **resolution-independent shape/layout definitions**, draw rectangles/lines/paths/outlines and icons at final native pixel density, rasterize antialiased text at final size, and use actual SVG/vector *source* icons or original parametric strokes rasterized/cache-keyed per display scale when justified. Never satisfy this request by rescaling 960x640 screenshots, a low-res UI atlas, text rendered at one fixed size, distorted block texture or an unbounded cache of scaled surfaces. Do not add an entire new GUI engine or pretend a vector engine ships by default. Keep Minecraft sprites crisp (respect intended nearest-neighbor treatment), do not blur them to fake UI polish.
- **DPI and layout:** audit actual window size vs drawable size, input-coordinate transform, Windows DPI awareness and relevant SDL/Pygame backend behavior **before changing flags**. Do not blindly enable `pygame.SCALED` or high-DPI switches that break the renderer/camera. Derive draw bounds, hitboxes and keyboard focus from one layout computation. Reflow rather than merely scale down at 960x640, and preserve 1200x800 and 1920x1080, maximized/windowed/borderless/fullscreen, text scale >=125%, and Windows display scaling 100/125/150% (200% where available). Test resize back and forth, monitor change when possible, minimizing/focus return and context recreation. Preserve camera world anchor and click/pick alignment. No UI can paint outside its intended clip region, cover essential permanent status, become unreadable, or consume clicks invisibly after fading.

## Contextual choreography: fewer controls, zero lost features

- The default is **compact top Build/Library/Tools/World/Menu anchors plus a persistent settings/reveal affordance**, with subtle visual hierarchy; bottom-center Minecraft hotbar, initially present while actively building. The editor itself should occupy the full drawable canvas behind overlays; closed drawers must not reserve the old right-sidebar width.
- **Auto-hide hotbar** and expanded lower-left contextual options after a measured quiet interval (roughly 4 s to prototype). Hover over the bottom-edge hot zone reveals hotbar immediately, selecting 1–9 reveals selected slot briefly, and clicking/pinning/keyboard focus holds it. Allow `Always visible`. Hotbar edits, active drags, selection, brush, fill, placement preview, special-block manipulation, modal interactions, tooltips and narration must never lose their controls partway through a gesture. The current block/tool identity, unsaved state and active non-default editing mode remain plainly recoverable even in quiet mode. Hidden widgets cannot intercept world clicks; animation must not reflow/recenter camera or invalidate geometry. A clear visible/keyboard route reveals everything after focus loss, resize, or a mouse/keyboard user operation.
- **Clean Canvas** explicitly hides essentially all nonessential overlay chrome for uninterrupted contemplation/screenshots, but offers a reliable reveal/settings route and must leave editing/session state untouched. For now don't make all top anchors auto-hide *by default*; expose experimental future-B/full-hide preference only if it can use exactly the same visibility policy without feature duplication.
- **Real migration, not a study:** the current `docs/reviews/pass1-revision2/ui_study.py` has a hard-coded 12-item materials grid and placeholder Tools/World commands; `Code/ui/workshop.py` still deliberately retains a legacy palette behind an opt-in switch. Replace these *in the working editor* with the full existing block catalog (465 known identities, no inferred fixed limit), fast search, scroll, category/filter, favorites/recent, selection, hotbar assignment and explicit material properties. Preserve the full `PASS1_DIRECTION_REVISION` capability destination map and every callable command: advanced selection/clipboard/blueprints, fill/replace/brush/mirror/radial, layers/X-ray/minimap option, environment/terrain/weather/light/simulation, world map, tutorial, Redstone Lab, imports, settings, history, save/undo, all library tabs and native side previews. Shared command resolver owns keyboard/button semantics; no new world/undo/simulation implementation.
- World/Biome/Structure/Saved Builds Library has a deliberate wide list+preview overlay with named `Open` versus `Place`, cancellation, progress and preservation of live scene if dismissed; don't automatically place a selected thumbnail. Only the needed controls are visible during an operation, with a pin and keyboard recovery. Modal input/press-release precedence must remain correct.
- **Whole-app audit:** every UI surface should participate in the same visual/typographic system *where it is actually a UI*, not blindly redesign scene world geometry. Include splash, initial opening hints (without changing its approved pacing), editor, Library, preview shelves, settings, help/hotkeys, tutorials, World Map, Redstone Lab, loading/save/errors, confirmation, overlays and return flow. Keep operating-system native file dialogs native where appropriate, but avoid inconsistent in-game wrappers.
