Continuous orbit feasibility
Current app uses four projected sprite views; a continuous orbit cannot be obtained
by merely sliding that camera. A separate bounded-scene mesh renderer was probed
in .qa/sanctuary-preview/orbit_probe.py using existing raw textures and OpenGL via
Windows ctypes, without installing dependencies or changing the app renderer.
Depth-buffered opaque faces and sorted translucent faces are batched.
See orbit-feasibility.json for measured GPU/driver, counts and timings. The hidden-
window probe covers rendering and glass sorting only, with glFinish. It excludes
UI, particles, ray picking, audio, display switching, visible swap/vsync and
end-to-end input latency. No finished-game FPS claim follows from these numbers.

Recommendation: confine GPU rendering to the two presentation scenes. Validate
slider/ray picking at several angles, transparent depth ordering, native FHD
framing, fullscreen/windowed restoration and fallback behavior before release.
Do not migrate the editor or introduce a general timeline framework.
